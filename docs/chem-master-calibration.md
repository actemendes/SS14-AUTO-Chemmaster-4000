# Ручная калибровка Химмастера

> Это документация legacy developer-калибровщика `chemmaster-input.json`. Готовый
> `ChemMasterAssistant.exe` не использует координаты с вручную размеченного снимка:
> `LiveCalibrationManager` читает прямую client-relative геометрию Control из свежего
> snapshot и сохраняет отдельный `chemmaster-calibration.json` schema 2 с DPI,
> client size, UI scale и рамкой панели. Тесты не перезаписывают оба пользовательских
> профиля.

Этот отдельный инструмент размечает неподвижный снимок для разработки и виртуальных тестов. Сам по себе он не подключается к игре, не записывает её память, не перехватывает глобальные клики и ничего не отправляет в сеть.

## Запуск

Из корня проекта:

```powershell
.\calibrate.ps1
# Или сразу с изображением:
.\calibrate.ps1 -ImagePath .\calibrations\input-reference.png
```

Сборка использует установленный в Windows .NET Framework 4.x, без скачивания пакетов. Выходной EXE получает имя с хешем исходников; уже открытые версии не перезаписываются.

1. Откройте PNG/JPG/BMP или вставьте снимок из буфера кнопкой в программе. Подойдёт снимок окна SS14 или обрезанная панель, но нужно понимать, что её начало ещё не является началом игрового окна.
2. Выберите вкладку «Вход» или «Выход», соответствующую снимку. Для каждой вкладки сохраняется отдельный профиль.
3. Обведите рамку панели и отметьте центры основных кнопок. Любой шаг можно выбрать в списке и исправить.
4. Для входной ёмкости и буфера отдельно обведите видимую область строк без заголовка и полосы прокрутки. На первой строке отметьте дозировки **один раз**, затем кнопку «1» второй строки. Это задаёт столбцы и вертикальный шаг всех строк. Для полного входного профиля получаются 32 шага, независимо от числа реагентов.
5. Подтвердите, что оба списка на исходном снимке прокручены в начало. Пустая мензурка не даёт данных для её сетки: такой профиль нужно сохранить черновиком.
6. Сохраните JSON. Для продолжения откройте тот же снимок и выберите «Загрузить разметку…». Хеш проверяет соответствие изображения профилю; случайно загрузить точки от другого снимка нельзя.

Колесо меняет масштаб просмотра, средняя кнопка перетаскивает изображение. Разметка всегда сохраняется в пикселях **исходного изображения**, а не уменьшенного/увеличенного просмотра. Координаты X не интерполируются: кнопки «1», «100» и «Всё» имеют разную ширину. Кнопка «Уничтожить» не входит в профиль.

Снимки и личные профили находятся в `calibrations/` и исключены из Git. Ваш снимок 562×567 сохранён как `input-reference.png`; к нему подготовлен `input-reference-draft.json`: основные кнопки и 11 столбцов буфера, шаг строк 24 пикселя. Входная сетка и подтверждение начала прокрутки оставлены незаполненными. Нижняя частично видимая строка не включена в область доступных строк. Это черновик, не готовый профиль для исполнения.

## Какие вещества можно читать

Существующий `chemMaster.raw` содержит:

- `input.reagents`: ID и количество каждого вещества во входной мензурке;
- `output.reagents`: состав выходной ёмкости, если она хранит жидкость;
- `bufferReagents`: ID и количества в буфере;
- `sortingType`, режим переноса, вместимость ёмкостей и другие параметры.

Количество хранится в сотых долях единицы: `17500` означает `175u`. В сохранённой записи от 28 августа чтение буфера подтверждено; входная мензурка в использованном кадре была пустой. Это данные последнего присланного клиенту состояния, а не гарантия включённого питания или возможности выполнить действие.

**Индекс raw-списка не равен индексу строки на экране.** Клиент отдельно сортирует буфер. В новом `chemMaster.ui` считывается дерево уже созданных контролов: `NameScope → BufferInfo/InputContainerInfo → _orderedChildren → ReagentButton.Id`. Поэтому для порядка не нужны OCR, перевод названия или попытка повторить сортировку по русскому алфавиту.

```json
{
  "source": "live-ui-controls",
  "rowOrderValid": true,
  "inputRows": [{ "rowIndex": 0, "prototype": "Water" }],
  "bufferRows": [
    { "rowIndex": 0, "prototype": "Oxygen" },
    { "rowIndex": 1, "prototype": "Nitrogen" }
  ],
  "error": ""
}
```

Пример синтетический. `rowIndex` нумеруется от нуля и относится ко **всему** списку, а не только видимым строкам. ID всех кнопок в строке проверяются; набор строк сверяется с raw-составом. При несовпадении, дубликатах, неизвестной структуре или промежуточной перерисовке `rowOrderValid=false`, списки очищаются, причина попадает в `error`. Чтение химического состава при этом остаётся независимым. Старые записи без `ui` продолжают открываться, но не дают подтверждённого порядка UI.

Техническая основа проверена по [коду ChemMasterWindow SS220](https://github.com/SerbiaStrong-220/space-station-14/blob/master/Content.Client/Chemistry/UI/ChemMasterWindow.xaml.cs) и [упорядоченным контролам RobustToolbox](https://github.com/space-wizards/RobustToolbox/blob/master/Robust.Client/UserInterface/Control.cs). Проверена 29 августа 2026 года; новые версии игры могут изменить поля. Извлекатель прошёл тест чтения настоящей памяти отдельного процесса с моделью этих типов и живую проверку полных рецептов Dylovene и Hyronalin на локальном пользовательском сервере, включая промежуточное вещество и подтверждённую прокрутку. Подробности и ограничения записаны в `chem-master-live-validation.md`.

## Чего legacy-профиль не гарантирует

`PreviewReagentPoint` legacy-калибратора вычисляет только точку для offline-предпросмотра и не нажимает её. Production executor вместо этого использует прямые прямоугольники фактических dose-кнопок из `ChemMasterUiReader`, проверяет стабильность прокрутки и выполняет отдельную транзакцию с новым State после каждого одиночного ввода.

Один сохранённый профиль и `rowOrderValid` сами по себе **не подтверждают** активную вкладку, выбранный игровой аппарат, положение прокрутки, свежесть снимка, питание, доступность кнопки или отсутствие другого оператора. Production reader/executor проверяет эти условия заново, отклоняет несколько активных ChemMaster BUI и ставит выполнение на паузу при неоднозначном изменении. Кэшированный адрес BUI используется только как промежуточное наблюдение анимации прокрутки: перед любым следующим вводом обязателен полный поиск кандидатов, а исчезнувший/перемещённый GC объект автоматически вызывает полный scan.

## Проверки

```powershell
.\test-chemistry-calibration.ps1
.\test-chemistry-ui-reader.ps1
.\test-chemistry-planner.ps1
.\test-chemistry-recipes.ps1
```

34 теста legacy-профиля проверяют сериализацию, отдельные столбцы, шаг строк, смещение, прокрутку, обрезание, неизвестные/неоднозначные ID и отклонение неполных данных. Отдельный UI-reader suite использует ClrMD для чтения fixture-процесса и проверяет raw-поля, порядок/геометрию контролов, неоднозначные окна, invalid cached address, close/reopen и обязательное полное обнаружение второго BUI; SS14 для него не требуется и не читается. Production executor имеет дополнительный offline suite с fake snapshot/input.
