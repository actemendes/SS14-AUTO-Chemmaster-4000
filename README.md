# ChemMasterAssistant для SS14

Автономный локальный помощник для открытого интерфейса «Химмастера 4000». Он читает клиентское состояние согласованными read-only ClrMD-снимками, рассчитывает выполнимые партии по локальному каталогу и выполняет только обычные клики Windows. После каждого клика новое состояние аппарата обязательно подтверждается до следующего действия. Быстрые адресные чтения используются только для наблюдения за анимацией прокрутки; перед любым следующим вводом всё равно обязателен полный поиск всех открытых ChemMaster BUI.

Runtime не использует GPT, ChatGPT, Codex, Computer Use, браузер, OCR, интернет, административные API или серверные команды. Записи в память клиента и BUI-инъекции нет.

## Готовое приложение

Переносимая папка создаётся командой:

```powershell
.\publish.ps1
```

Результат: `ChemMasterAssistant\ChemMasterAssistant.exe` вместе с self-contained .NET runtime, локальными JSON-каталогами, настройками, непривязанным шаблоном калибровки и пользовательским README. Установленный .NET для запуска готовой папки не требуется.

`publish.ps1` создаёт чистый релиз и намеренно откажется заменять папку, в которой уже появились журналы или привязанная пользовательская калибровка. Для отдельного staging-каталога используйте `-StagingParent <каталог-внутри-проекта>`; package/UI-тест делает это автоматически и не трогает рабочую папку приложения.

Проверка пакета без запуска игры и без доступного .NET в `PATH`:

```powershell
.\ChemMasterAssistant\ChemMasterAssistant.exe --smoke-test
```

Приготовление полностью offline. Интернет используется только отдельным developer-скриптом `update-chemistry-recipes.ps1`, когда разработчик явно обновляет каталог из wiki.

## Первый безопасный запуск

1. Запустите один клиент SS14, откройте обычный интерфейс Химмастера и загрузите исходные реагенты.
2. Запустите `ChemMasterAssistant.exe` из всей распакованной папки.
3. Подключитесь к автоматически найденному клиенту. При нескольких подходящих клиентах программа откажется выбирать один наугад.
4. Нажмите «Калибровать текущее» и явно подтвердите профиль открытой панели. Поставляемый профиль намеренно пуст.
5. Убедитесь, что входная мензурка пуста. Программа не очищает и не смешивает неизвестный остаток автоматически.
6. Найдите одно или несколько лекарств, укажите объём и режим `make` или `ensure`, просмотрите план и затем явно начните выполнение.
7. Для немедленной блокировки новых кликов нажмите глобальную `F12`. После неё нужен отдельный явный сброс и новый запуск.

Если во время выполнения перейти в другое окно, помощник безопасно поставит операцию на паузу. Кнопка «Продолжить» сначала возвращает фокус проверенному окну SS14 и только затем снимает паузу. Если Windows не смогла активировать игру или фокус сразу потерян, пауза сохраняется и ввод не выполняется.

Полная инструкция для нового пользователя находится в `package\README.md` и копируется в релиз.

## Архитектура

- `ClientDiscovery.cs` — строгий выбор ровно одного `SS14.Loader`, проверка PID/окна и DAC именно для фактически загруженного `coreclr.dll`.
- `ChemMasterBuiReader.cs`, `ChemMasterUiReader.cs`, `ChemMasterSnapshotSource.cs` — согласованные snapshot raw State и живых UI-контролов, точные prototype ID, порядок строк, геометрия, вкладка и `Value/ValueTarget`; полный scan кэширует только уже проверенный адрес BUI для быстрых промежуточных наблюдений, а каждый путь к физическому вводу требует полного набора кандидатов.
- `LiveCalibrationManager.cs` — schema 2, физические client-relative координаты, DPI, размер клиентской области, UI scale и рамка панели; профиль не масштабируется молча.
- `RecipeCatalogService.cs`, `ChemistryPlanning.cs`, `ChemistryVirtual.cs` — локальный каталог revision 11655, планирование `make`/`ensure`, промежуточные вещества, резерв целей, катализаторы, конкурирующие реакции и партии по вместимости.
- `ExecutionSequencePlanner.cs`, `ChemMasterExecutor.cs` — конечный автомат и транзакции «свежий snapshot → стабильная строка → один клик → точное подтверждение». Timeout, внешнее изменение, закрытие панели и несовпадение геометрии не повторяют клик.
- `WindowsGameInput.cs` — обычный `SendInput`, проверка активного окна/PID/размера/DPI/точки непосредственно перед вводом и аварийная блокировка.
- `ActionJournal.cs` — локальный JSONL с планом, снимками до/после, строкой, дозой, точкой, ожидаемой/фактической разницей, причиной остановки и телеметрией чтения (`full`, `fast-cache-hit`, `fast-fallback-full`, полное время source-read с ожиданием gate и проверками окна).
- `src\ChemMasterAssistant` — локальный WinForms UI: подключение, содержимое, поиск и мультивыбор целей, предпросмотр, старт, пауза, продолжение, отмена, внешнее изменение, F12 и журналы.

Нагрев, электролиз, центрифугирование и другие внешние операции показываются как ограничения и автоматически не выполняются.

## Developer CLI и каталоги

Локальные данные:

- `src\ChemMaster\chemistry-recipes.json` — 237 веществ и 215 вариантов рецептов;
- `src\ChemMaster\chemistry-game-rules.json` — зафиксированные игровые реакции виртуального стенда;
- `src\ChemMaster\chemistry-selections.json` — полный список целей смешивания Химмастера плюс удобные медицинские категории;
- `tests\fixtures\chemmaster-input.test.json` — отдельная тестовая калибровка.

Read-only CLI и планировщик:

```powershell
.\run.ps1 --read --json
.\run.ps1 --plan "Epinephrine=20;Tricordrazine=10"
.\run.ps1 --check "@brute=10"
.\run.ps1 --simulate .\tests\scenarios\medicine-cycle.json --json
```

Legacy developer-сборка, не релизное приложение:

```powershell
.\build.ps1 -Offline
```

`-Offline` не загружает зависимости. Если локальный tool-cache ещё не подготовлен, команда завершится понятной ошибкой. Скрипты сборки и тесты не перезаписывают пользовательский `chemmaster-input.json`.

## Тестирование

```powershell
.\test.ps1
```

Набор покрывает калибровку и геометрию, ClrMD UI-reader в отдельном fixture-процессе, целостность каталога, планировщик, сотни виртуальных химических сценариев, транзакционный executor с fake snapshot/input, три offline CLI fixture и release-сборку. Отдельно проверяются возврат фокуса при Resume, причинная последовательность снимков, запрет ввода после TOCTOU-потери фокуса/курсора и обязательный полный scan после быстрого наблюдения. SS14 и настоящий Windows-ввод в автоматических тестах не используются.

Отдельные команды:

```powershell
.\test-chemistry-calibration.ps1
.\test-chemistry-ui-reader.ps1
.\test-chemistry-recipes.ps1
.\test-chemistry-planner.ps1
.\test-chemistry-virtual.ps1
.\test-chemistry-executor.ps1
.\test-package-ui.ps1
```

## Граница живой проверки

Живые клики разрешены только на принадлежащем пользователю сервере и только через обычный интерфейс. Полные рецепты Dylovene и Hyronalin успешно приготовлены и возвращены в буфер с подтверждением каждого клика новым State; Hyronalin закрыл расширенный live-сценарий с промежуточным веществом. Точный статус сценариев, исправления прокрутки и двух fail-closed остановок описан в `docs\chem-master-live-validation.md`.

Обновление внутреннего layout SS14 может потребовать совместимого обновления reader’а и новой калибровки. Исполнитель не запускают, пока не подтверждены открытая панель, владение тестовым сервером и безопасное исходное состояние. После закрытия панели или потери соединения сначала требуется новое read-only чтение; автоматический retry запрещён.
